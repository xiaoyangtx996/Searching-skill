# 街道级实锤方法（旁挂）

> **旁挂文件**：`SKILL.md` 是「线索 → 结论」规则表；本文补足**「怎么把结论坐实」**的方法链。
> 素材来源：用户自备经验（网络迷踪入门指南 / Vol.2 文字 / Vol.5 航班）+ 本项目已有工具。

## 〇、POV 是**通用范式**，不限于公交

**用户要点（关键）**：

> 「有些地方**是没有街景的**，但是如果搜索对应城市相关的**公交车的 POV 视角**，
> 就能在他视频里面**路过的那一瞬间**看到对应的街景；
> 也或者是其他对应的 POV 第一视角，可以是**高速公路上的**，也可以是**无人机 POV、航拍 POV**，
> 反正**不限于任何关键词**，反正就是 POV。
> 我希望你识别到图片或者通过其他 Skill 拿到一些信息之后，
> **再通过这个信息构造相对应的 POV 视角进行实锤**。」

### 三条核心认识

**① POV 补的正是"没街景"的洞**

街景车没去的路（县道、乡道、山区、新开发区、厂区、景区内部），
**本地人开车/骑车/走路时会拍下来**。所以：

> **街景缺失 ≠ 无法实锤。POV 视频就是"民间街景车"。**

尤其是**路过的那一瞬间**——目标点可能只在视频里出现几秒，但够了。

**② POV 不限于任何交通工具/视角**

| POV 类型 | 搜索词 | 擅长场景 |
|---|---|---|
| 公交 POV | `<城市> <线路> 前方展望` | 城市道路、站点 |
| 自驾 POV | `<城市> 自驾 POV` | **高速公路**、国道、郊野 |
| 高速 POV | `<高速名> POV` / `<城市> 高速 行车` | 服务区、跨江桥、隧道 |
| **航拍/无人机 POV** | `<地点> 航拍 POV` / `<地点> 无人机` | **无路可达**处、山区、海岸、工地 |
| 骑行 POV | `<城市> 骑行 POV` | 小巷、绿道、堤岸 |
| 步行 POV / walk | `<地点> walk` / `<地点> 4K walk` | 步行街、景区、小区内部 |
| 摩托 POV | `<城市> 摩托 POV` | 东南亚、乡村 |
| 火车/地铁 POV（展望） | `<车次> 展望` / `<线路> 前方展望` | 铁路沿线、站场 |
| 船 POV | `<航线> 船 POV` / `<码头> 实拍` | 渡口、江面、港口 |
| 缆车/索道 POV | `<索道名> POV` | 山岳景区 |

**③ 流程是「先识别 → 后构造」**

```
识别出信息（图片线索 / 其他技能产出）
        ↓
确定层级（国 / 省 / 市 / 区 / 街道 / 线路 / 设施 / 机构）
        ↓
构造对应的 POV 搜索式（本表）
        ↓
搜视频 → 逐帧比对 → 实锤
```

## 一、适用场景

- 目标图是**街景/门脸/路口/道路/设施**，已大致定位，但要**坐实**
- 该地**百度/腾讯全景缺失**（街景车没去）→ **POV 是唯一替代**
- 目标在图里**只在某一瞬间出现**（如路过）→ POV 正好按时间轴走
- 需要**独立来源**印证（见 `docs/证据与置信度框架.md`：属 A/B 级，独立于玩家社区语料）

### 无街景场景的**优先次序**

```
① 公交 POV（城市道路最全）
② 自驾/高速 POV（郊野、国省道）
③ 骑行/步行 POV（小巷、景区、绿道）
④ 航拍/无人机 POV（无路可达、山区、海岸、工地）
⑤ 火车/metro/船 展望（沿线、站场、水面）
```

**一路搜不到就换一路**：公交没有 → 自驾；自驾没有 → 骑行；
都没视频 → **换航拍 POV**（航拍覆盖往往比行车更全，因为游客爱拍）。

## 四、判读要点（通用）

- 视频里的**招牌、树、路灯、护栏、路牌、楼体、山形**与目标图逐一比对
- POV 可**反复暂停** → 比静态街景更好用；**"路过那一瞬间"就够**
- 注意**时差**：视频年份与目标图不一致时，只比**不易变的**（楼体、桥梁、路型、山形）
- **一层搜不到就降一层**：市搜不到 → 区 → 街道；也可**升一层**再交叉
- **航拍 POV 的独特价值**：能看到**地面视角看不到的**（路网走向、建筑布局、
  与周边的关系）——反过来印证地面照片的方位

### 输出要求

判读报告里**必须给出已识别层级对应的 POV 搜索式**（可直接复制去搜），例如识别到「重庆市渝中区」：

```
POV 实锤搜索式（复制即用）:
  城市级: 重庆 骑行 POV        / 重庆 自驾 POV
  街景级: 重庆 walk            / 重庆 4K walk
  区级  : 渝中区 POV           / 渝中区 实拍
  航线级: 重庆 402路 前方展望
  航拍级: 渝中区 航拍 POV      / 解放碑 无人机
```

## 三、街区几何：先建模再看地图

用户方法（**第二步：元素级审图 → 建模俯视图**）：

1. 从照片提取：**路口形状、车道数、隔离带、建筑相对位置、朝向**
2. 在脑中/纸上画**俯视示意图**（不求精确，求拓扑关系）
3. 到地图找**符合这个拓扑**的交叉口
4. 用街景/POV 视频验证

**关键**：先看**关系**（谁在谁对面、几个路口、是否单行道），再看**细节**（招牌、颜色）。
纯靠细节搜图容易撞车；靠拓扑能大幅缩小范围。

## 四、路牌信息（即使看不清字）

用户方法（**第七步：路牌类**）：

1. 路牌能判断**道路性质**：分流、几车道、单向/双向
2. **字看不清也有用**：路牌的**布局、颜色分区、箭头数量、牌面数量**
   本身就有地域/道路等级特征（如高架导向牌 vs 城区指路牌 vs 景区棕牌）
3. 放大 → 比**版面结构**而非文字 → 反推道路等级与地区风格

> 与 `language-script`、`infrastructure` 两域配合：文字域管"读得出什么"，基建域管"牌型属哪类路"。

## 五、Overpass Turbo（结构检索）

用户方法（**第八步**）：观察画面里**两种不同要素**，指定坐标区域，构造 Overpass 查询。

- 网页版：https://overpass-turbo.eu （可视化，适合手工调）
- 本项目脚本：`geo-sleuth/scripts/osm.py`（命令行，`near`/`intersect`/`crossings` 等）

**例**：画面里"河湾边的教堂" → `osm.py near` 找"河附近有教堂"的点；
"铁路与输电线交叉处" → `osm.py intersect`。

> ⚠️ 国内 OSM 数据不全（小店、小区内部基本没有），结果**只能当候选，不能当排除依据**。

## 七、局限（必须如实说明）

- POV 视频**不是全覆盖**：冷门县城、乡村道路常常没有
- 视频**有裁剪与压缩**，细节可能不如街景清晰
- 比对**受时差影响**：店招、车辆、行道树都会变；老视频不比新招牌
- **不能反证**：搜不到视频 ≠ 该地没有这段路
