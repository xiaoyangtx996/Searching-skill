## 一、什么情况该用「大数据筛查」

**判据：图里有两个可命名地物，且各自数量都很大。**

| 场景 | 常规做法的问题 | 大数据筛查 |
|---|---|---|
| 图里「好客连锁」+「XX银行」 | 广东「好客连锁」上百家、银行上千家，**人力比对不现实** | 抓全两边，算两两距离，看最近几对 |
| 图里「汉庭优佳酒店」 | 全国近千家，**光上海就 112 家** | ❌ 大品牌不能当起点（见下） |
| 图里招牌「陶源丰」 | 唯一性好，**直接搜就中** | ❌ 不需要筛查，普通查询即可 |

**关键决策**：

```
画面里的两个词，谁的数量少、谁最独特 → 用哪个当"锚"
只有两个都量大、又都不独特时，才上大数据筛查
```

> 反面案例（原文）：用地图搜「汉庭优佳酒店」——**全国近千家，光上海就有 112 家**。
> 正确做法是找画面最右侧垂直招牌上那三个字「陶源丰」→ **唯一检索结果** → 直接命中平遥。

## 二、两种 POI 邻近算法（本地面向不同场景）

### ① 固定半径「A 附近有 B」（快，适合半径能估准）

```bash
py geo-sleuth/scripts/poi_pick.py --kw 中国银行 --near 渝香饭店 --radius 300
```

**原理**：先查 A，再对每个 A 查「N 米内有没有 B」。
**适用**：肉眼能大致估出两者距离（如"隔着一条马路，约 50 米"）。
**风险**：**半径估错就漏**——估 300 实际 600，答案直接被滤掉。

### ② 全量笛卡尔积比对（慢，但不怕估错半径）★推荐用于量大场景

```bash
py geo-sleuth/scripts/poi_pick.py --kw 好客连锁 --cross 银行 --city 广东省 --pages 2 --limit 8
```

**原理**：抓全 A 和 B → 算**所有两两距离** → 按距离升序排 → 人工只看前几条。
**适用**：两边都上百个，且**不知道确切距离**（只能判断"很近"）。
**优势**：无需猜半径；答案就在最近的那几对里。

**实测（复现原文案例）**：

```
抓全：好客连锁 87 个 | 银行 225 个
  1. 相距   103.9 m
      A: 好客连锁(百花洲店)        [广东省梅州市梅江区]
      B: 中国人民银行(梅州市分行)   [广东省梅州市梅江区]
  2. 相距   355.9 m  惠州…
  3. 相距   604.5 m  惠州…
```
→ 第 1 条即 **梅州市梅江区**，与原文答案（梅州市江南新中路）**同一城市**。✅

> 原文作者用 Node + MySQL 的 `st_distance` 做同样的事，
> 本地实现用 `haversine_m()`（纯 stdlib，无需数据库）。

## 三、地图开放平台（原文第 3.1 节）

| 平台 | 链接 | 说明 |
|---|---|---|
| **高德开放平台** | https://lbs.amap.com/ | 国内 POI 覆盖最好；本地 `poi_pick.py` 用它 |
| **百度开放平台** | https://lbsyun.baidu.com/ | 国内另一主力 |
| **OpenStreetMap** | https://www.openstreetmap.org/ | 开源；**海外数据翔实，中国大陆偏少** |
| **Google Maps Platform** | https://developers.google.com/maps | 国外主力 |

**分工**：国内 → 高德/百度；国外 → OSM/Google。
**注意**：OSM 里**中国的国界线是错误的**，且大陆地图数据偏少，但海外非常翔实。

## 四、OSM 系数据挖掘工具

### Overpass Turbo（https://overpass-turbo.eu/）

按**位置逻辑**搜索所有符合条件的地点，替代人工「扫图」。
网站有 **Wizard** 功能，输入自然语言自动生成查询代码。

**例**：找「与军事用地距离 200 米内的地铁站」

```overpassql
[out:json][timeout:25];

// 获取所有军事用地，保存为 military
(
  nwr["landuse"="military"]({{bbox}});
) -> .military;

// 获取所有与 military 距离 200 米内的地铁站
nwr[railway = station](around.military: 200);

out body;
>;
out skel qt;
```
→ 广州某区域返回 **13 个**结果，可「Export」导出 JSON 再处理。

**要点**：`nwr` = node + way + relation 三种要素一起搜；
`around.X: N` = 与集合 X 距离 N 米内。
**本地替代**：`geo-sleuth/scripts/osm.py`（`near` / `intersect` / `crossings` 等子命令）。
**限制**：国内访问 Overpass 需代理；国内 OSM 数据不全，**结果只能当候选，不能当排除依据**。

### TagFinder（http://tagfinder.herokuapp.com/）

帮你**找到 OSM 里的标签名**，供 Overpass 查询使用。

**例**：想找「风力发电机」→ 搜 "Wind Turbine" →
系统告诉你用 `generator:method=wind_turbine` 和 `generator:source=wind` 两条标签检索。

> **用途**：不知道某个设施在 OSM 里叫什么标签时，先用 TagFinder 查标签名。

### WhatIsWhere（https://www.whatiswhere.com/）

同样是基于 OSM 的 POI 搜索工具，**与 Overpass Turbo 类似但不需要写语法**。
适合快速试查、语法不熟时使用。

## 五、执行顺序（写进流程）

```
① 图里读出两个（或更多）文字/品牌名
        ↓
② 判断"独特性"与"数量"
   ├─ 有独特名（如「陶源丰」）→ 普通查询 poi_pick --kw 即可，直接命中
   ├─ 有一个量小 + 一个量大 → 用 --near（半径法）
   └─ 两个都量大 → 用 --cross（笛卡尔积），看最近几对
        ↓
③ 结果交给画面其他线索筛选（颜色/车型/季节/建筑）
```

**硬规矩**：
- **大品牌不能当起点**（汉庭/麦当劳/中石化…全国上千家），要优先找**独特名词**
- 笛卡尔积结果**只看前几条**——图里两物目测多远，就取距离相近的那对
- POI 是**独立证据源**（见 `docs/证据与置信度框架.md`），不依赖玩家社区语料

## 六、局限

- 高德/百度 POI **有收录偏差**：新开的店、小县城店常缺；**查不到 ≠ 不存在**
- 坐标是 **GCJ-02（高德）/ WGS84（天地图）**，两者不能直接混算距离（本脚本按源分别算）
- 笛卡尔积**请求量大**（两个各 500 条 = 25 万次距离计算，抓取本身要翻几十页），注意配额
- 同名连锁不区分加盟/直营，**同品牌不同店不能互证**
