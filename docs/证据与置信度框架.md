# 证据与置信度框架（强制）

> 用户提出的问题：**「每一个 skill 和 MCP 识图都应该给出置信度」**。
> 本文件回答：置信度怎么算、什么才算真正的互证。

---

## 一、为什么需要（真实教训）

### 教训 A：OCR 的高置信度会骗人

曾有用户发来一张行车记录仪截图，OCR 从画面里读出一段**数字，置信度 0.999**。
把该区域放大 3 倍核实后确认：**那是墙面污渍，不是文字**。

> **OCR 的 `conf` 是「这个字长这样」的字形置信，不等于「这里真有字」。**
> 0.99 的高分反而更危险——它会让你把一个污斑当铁证。

### 教训 B：循环论证冒充互证

同一张图，Google Lens 给出了一个**具体地名**。
然后拿 Lens 给的这个词去搜规则库，命中了一条讲该地名特征的规则。

于是差点写成「Lens 和规则库互相印证」——**这是错的**：

1. 画面里**根本没有那条规则所述的证据**（是自己脑补的匹配）
2. 用引擎给的词去搜库，搜到什么都只证明「库里有这个词」，不构成独立验证

### 教训 C：同源证据不算互证

**元素层**（27 技能）来自 mizong.fun 论坛语料；
**区域层**部分来自图寻社区（语雀）。

两者都源自**同一个玩家社区的经验总结**。当它们「一致」时，
**这不是两个独立来源互证，是同一个来源说了两遍**。

## 二、证据分级（按可信度）

| 级 | 名称 | 说明 | 例子 | 可支撑 |
|---|---|---|---|---|
| **A** | 硬事实 | 机读数据 / 物理计算 / 官方标准 / **画面直接可见** | `phone.json` 号段、`sun.py` 太阳方位、车牌维基对照表、**照片里清晰可读的路牌** | 可单独定 L3–L4 |
| **B** | 权威整理 | 有署名、有据可查的社区/官方整理 | 图寻语雀教程（部分是 Plonk It 官方汉化）、国际云图标准 | 2 条可比 |
| **C** | 社区经验 | 论坛语料挖掘的倾向性规律（「多为」「常见」） | mizong.fun 蒸馏的 2,772 条元素规则 | ≥2 条**且**跨来源 |
| **D** | 机器推断 | 识图引擎、OCR、模型猜测 | Google Lens「图中可能是」、OCR 文本、sat_scan 相似度 | **只作线索**，绝不单独定级 |

### 关键规则

1. **A 级可以单独成立**（有 GPS = L4；画面清晰文字 = L3）
2. **C 级必须凑够 2 条且来自不同子域**才报 L2+
3. **D 级永远不能单独支撑结论**——它只能生成线索词，喂给 C 级规则匹配
4. **画面直接可见 > 任何文字资料**：照片里看得见的东西是 A 级

## 三、独立性判定（防止假互证）

**两条证据算「独立」的条件：数据源血缘不同。**

| 组合 | 独立？ | 原因 |
|---|---|---|
| 画面可见 × `phone.json` 号段 | ✅ 独立 | 图像 vs 官方号段库 |
| 画面可见 × `sun.py` 计算 | ✅ 独立 | 图像 vs 天文物理 |
| 元素层规则 × 区域层规则 | ⚠️ **弱独立** | 同属玩家社区经验（mizong.fun / 图寻），只能算 1.5 条 |
| 元素层规则 × 元素层规则 | ❌ 不独立 | 同一语料 |
| 区域层 × 区域层（同一作者/同一语雀文档） | ❌ 不独立 | 同一来源 |
| **Lens 给词 → 搜库命中** | ❌ **循环论证** | 库里当然有这个词 |
| OCR 文本 × 用它搜到的规则 | ❌ **循环论证** | 同上 |

### 血缘图

```
mizong.fun 论坛 ──→ 元素层 27 技能（2,772 条）      ┐
                                                   ├─ 同源：玩家社区经验
图寻语雀社区 ─────→ 区域层 161 文件（21,953 条）    ┘

维基/官方 ────────→ geo-sleuth/data/（车牌、区号表）  ─┐
物理计算 ─────────→ sun.py / ShadowFinder            ├─ 独立来源
官方号段 ─────────→ phone.json                      ─┘

图像本身 ─────────→ 画面直接可见的内容              ── 最强，独立于所有文本
识图引擎 ─────────→ Lens / 百度 / 必应              ── 机器推断，仅线索
```

## 四、执行规则（写进流程）

### 每张图的证据表必须带「源」和「级」

```
证据                    源                    级   独立组
画面:蓝白护栏            图像                   A    #1
画面:黄色出租车          图像                   A    #1
区域规则:蓝白护栏→重庆   区域层(图寻)           C    #2
元素规则:黄车顶灯竖放    元素层(mizong)         C    #2   ← 与上条同组！只算 1.5 条
Lens:设施类型判断        识图引擎               D    —    仅线索
OCR:疑似文字(conf 0.999) 图像→OCR              D    —    ⚠️ 需回原图核实，本例为误读
```

**报 L2+ 的条件**：独立组 ≥2，且至少一组是 A 或 B。

### OCR 置信度的特殊处理

| OCR conf | 处理 |
|---|---|
| >0.9 | **不算可靠**——必须回原图放大核实（污斑/纹理常给高分） |
| 0.3–0.9 | 标「待核」 |
| <0.3 | 丢弃 |

**交叉核验法**：同一个字在 `full` / `up` / `tile` 三个 pass 都读出来且一致 → 才算可信。
只在一个 pass 出现 → 极可能是误读。

### 识图引擎置信度

| 信号 | 置信 |
|---|---|
| Lens 给出具体地名 / 设施专名（含专有称呼） | 中（可作线索，需别处印证） |
| Lens 泛泛给出类别（如「高速公路」） | 低 |
| 百度「图中可能是X」 | 低（仅提名） |
| 引擎无结果 / 报错 | 无（**不等于画面无线索**） |

**⚠️ 引擎结果绝不能当唯一依据**：识别出「这是什么设施」只说明类型，
**不说明地点**。引擎认得而本地方案没收录的设施，会出现「引擎有、规则库无」的落差。

## 五、本框架修掉的真实缺陷

| # | 缺陷 | 状态 |
|---|---|---|
| 1 | OCR 高置信度的误读被当成文字线索 | ✅ 本框架第 4 节 |
| 2 | 用引擎给的词搜库 → 冒充互证 | ✅ 第 3 节「循环论证」 |
| 3 | 元素层 × 区域层被当两条独立线索 | ✅ 第 3 节血缘图 |
| 4 | 引擎认得某些设施，本地规则库 0 覆盖 | ✅ 已按此补录结构类规则 |
| 5 | 各技能没有统一的置信度输出 | ✅ 本框架 |

---

## 六、待办（已知缺口）

- **结构类设施靠"外形"判读的规则偏少**：引擎常能认出塔型、桥型、棚型等，
  而规则库缺对应条目 → 应在 `infrastructure/`、`landforms/` 持续补录
  （如"大跨越塔型"这类特征：矩形环网格塔身、V 形分腿、多分裂导线）。
- 各 `wlmz-*` 技能的规则若来自不同作者，应在区域层文件里标出作者，
  以便判定「同一作者 ≠ 独立来源」。
