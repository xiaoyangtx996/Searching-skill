# 技能互联 · 产出手册

> 本文件解决一个具体问题：**每个技能产出什么、该喂给谁**。
>
> 背景：全库 27 个技能，实测交叉引用后发现 **7 个技能只吃不出**（地理地貌、密码与加密、
> 时空文化、星空、航空航班、轮船、铁路高铁）——它们被算出结论后**没人接**，
> 判读流程在这里断掉。另有 `光影天文 → geo-sleuth` 这条本该是核心闭环的链路，
> 实测引用数偏低（光影仅被 4 个技能引用）。
>
> 本手册给每个技能补上「出口」，让判读结果能继续往下走，而不是停在某个技能里。

---

## 一、三层结构（先记住这个）

```
① 元素层（27 技能）      这「是什么」—— 车牌、护栏、植被、建筑、光影…
        ↓ 每条元素线索都要问「它能反推哪里」
② 区域层（区域定位）      这「在哪里」—— 中国 19+ / 世界 132+ / 元素 10+
        ↓ 收敛出候选后
③ 核验层（geo-sleuth）    这「经不经得起核对」—— 算数值、查表、排除、出证据图
```

**核心规则**：任何一层得出的结论，都必须显式交回下一层；**不许中途停下**。

## 二、出口表（每个技能产出 → 交给谁）

### 🔴 七个"孤岛"（原先是只进不出，本表补出口）

| 技能 | 产出什么 | **交给谁** | 怎么接 |
|---|---|---|---|
| **地理地貌** | 山体走向、岩性、雪线、地貌类型 | → `region` | 山体轮廓 → 反查城市（如"背后有南北走向雪山"→ 乌鲁木齐/西宁）；读 `landforms/references/山体判读.md` 六步法出结论后，进 `kb_search` 搜山体特征词 |
| **时空文化** | 推定日期 / 节日 / 季相 / 历史年代 | → `lighting-astronomy`（日期→太阳方位）、`region`（节日→地区） | 日期确定后**必须**跑 `sun.py pos` 验证画面光影是否自洽；节日/服饰进区域层查习俗地域 |
| **航空航班** | 机型 / 航司 / 航线 / 机场设施 | → `region` + `spatiotemporal-culture` | 航线走向 → 排除不在该航线上的城市；涂装 → 锁定航司基地 |
| **轮船** | 船型 / 船籍港 / 航线 / 港口设施 | → `region` + `infrastructure` | 船籍港文字 → 区域层；码头结构 → 基建层对照 |
| **铁路高铁** | 轨道型式 / 桥墩 / 接触网 / 车站 / 车型 | → `region` + `infrastructure` | 351 条规则里"某型式仅某线有" → 直接缩线路 → 城市 |
| **星空** | 星座 / 银河走向 / 光污染等级 | → `spatiotemporal-culture` + `lighting-astronomy` | 星座方位 + 时刻 → 纬度与季节；光污染 → 排除大城市 |
| **密码与加密** | 解出的明文 / 编码类型 | → `language-script` | 解密结果**必须**回灌人文文字做文本判读（字体、语言、地名） |

### 🟡 光影天文 ↔ geo-sleuth 闭环（补强）

| 步骤 | 谁做 | 产出 | 交给谁 |
|---|---|---|---|
| 1 | `lighting-astronomy` | 影子方向、太阳高度角、推定时刻 | → `geo-sleuth` |
| 2 | `geo-sleuth/sun.py locate` | 全球亮带（可能的纬度带） | → `region` |
| 3 | `region` | 带内候选城市 | → 交回 `geo-sleuth/board.py` |
| 4 | `board.py rank` | 排序 + 误差半径 | → 总技能出结论 |

**强制**：光影只要给出「可量化的方位/角度」，就**必须**走这个闭环；不许停在"画面是上午拍的"。

## 三、执行流程（每张图都这么走）

```
① sweep.py <线索…>          ← 27 个技能全部遍历，零命中也列表（防漏）
② 自动识图（MCP / intake.py）← 拿外部结果，补充画面外线索
③ 按「出口表」逐条交接       ← 上游结论必须换手给下游
④ 区域层查（kb_search）      ← 报 L2+ 的门禁
⑤ geo-sleuth 核验           ← 数值/排除/证据图
⑥ 出结论（L0–L4 + 互证）
```

**每一步都要留下产出物**，否则视为未执行。

## 四、自检清单（报结论前逐条打勾）

- [ ] `sweep.py` 跑过，**27/27 全覆盖**（不看命中数，看覆盖率行）
- [ ] 自动识图跑过（MCP 或 `intake.py`），结果已读
- [ ] 七个孤岛的出口**都问过一遍**：画面里有山/船/飞机/火车/night-sky/密码/日期吗？
      有 → 按出口表交接；没有 → 在输出里写"该域无线索"
- [ ] 画面有可量化光影 → 走过 `lighting-astronomy → geo-sleuth → region` 闭环
- [ ] `kb_search` 区域层有命中（**报 L2+ 的硬门禁**）
- [ ] 每个候选都有互证来源，不是单条规则
- [ ] 不确定项如实列出，不脑补

## 五、为什么这样设计（防漏原理）

**漏判的根源是"让 AI 判断该加载哪几个"**。重庆案例就是这么错的：AI 觉得
"黄出租车多城都有"，跳过了区域层，停在 L2；实际区域层三条规则直指重庆。

所以：

| 做法 | 结果 |
|---|---|
| AI 路由（挑几个技能） | ❌ 会漏，且**漏了不知道** |
| **脚本遍历（全走 + 报 0 命中）** | ✅ 漏不漏是脚本的事，可验证 |

本手册的「出口表」是同一思路的第二层：**不只加载要全覆盖，交接也要全覆盖**——
每个技能产出后必须问一次"这该给谁"，在输出里留痕。
