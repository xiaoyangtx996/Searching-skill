# 影子与太阳 · 本地计算

本文件是 `lighting-astronomy/SKILL.md` 的**旁挂补充**：规则库那份 SKILL.md 讲「线索 → 结论」，
这里讲「把那条结论**算出来**」，以及外部工具 ShadowFinder 的用法。

> 直接改正文下次重跑会被覆盖。所以新内容都放这里，SKILL.md 只留一行指针。

## 1. 三种工具，先选对

| 手头有什么 | 用哪个 | 产出 |
|---|---|---|
| 只看到影子/太阳，要判**朝向、时段、纬度带、季节** | `lighting-astronomy/SKILL.md` 的 172 条散文规则 | 线索 → 结论（倾向） |
| 有**时刻 + 影长比**，要在候选区上求**一条带** | `geo-sleuth/scripts/sun.py locate` | 地带 + 与候选区相交 |
| 有**时刻**，要看**全球**可能范围 / 想在 Colab 里画图 | ShadowFinder（本文件第 5 节） | 全球亮带 figure |
| 有**影子 + 已知地点**，要反推**拍摄时刻与日期** | `sun.py when` | 两组候选日期 + 敏感度 |
| 画面里有**太阳本身**，要定镜头朝向和画面里物体真实方位 | `sun.py compass` | 朝向区间 |
| 有**卫星电视锅** | `sun.py dish` | 经度范围 |

**一句话分工**：散文规则负责「能不能用太阳这条线索」，`sun.py` 负责「算成数值并进候选盘」，
ShadowFinder 只在「要一张全球图 / 要 Colab 交互」时才出手。
**不要用散文规则里的「多为」去替代一次实际计算**；也不要拿 ShadowFinder 的画图当证据图——
证据图用 `geo-sleuth/scripts/evidence.py`。

## 2. 影长比 ↔ 太阳高度角

公式只有一条：`太阳高度角 = atan(物体高 / 影长)`，只要**比例**，不需要真实尺寸。

| 影长比（影/物） | 高度角 | 影长比 | 高度角 |
|---|---|---|---|
| 0.1 | 84.3° | 1.2 | 39.8° |
| 0.2 | 78.7° | 1.5 | 33.7° |
| 0.3 | 73.3° | 2.0 | 26.6° |
| 0.5 | 63.4° | 3.0 | 18.4° |
| 0.7 | 55.0° | 4.0 | 14.0° |
| 1.0 | 45.0° | 5.0 | 11.3° |

```bash
uv run scripts/sun.py ratio --shadow 1.2          # 1:1.2 → 39.8°
```

**量的规矩（与 `SKILL.md` 一致，别省）**：选竖直物体（墙角、电杆、路灯杆）落在平地上的影子；
影子最好与画面平行；广角先校正畸变；同一张图里平地影必须互相平行，不平行就是地不平/物不直/人工光/拼图；
至少量两个物体取区间。**影长误差 20%，在 45° 附近会带来 6–8° 高度角误差。**

## 3. 散文规则 → sun.py 子命令 映射

`lighting-astronomy/SKILL.md` 里成串的「影子/太阳」规则，按这张表落到具体命令。
（`sun.py` 共 8 个子命令：`pos` `ratio` `locate` `when` `street` `facing` `compass` `dish`）

| 散文规则（线索 → 结论） | 落地命令 |
|---|---|
| 物体影子朝向与太阳方位相反 → 据影子反推太阳方位 | `sun.py pos --at <大致位置> --time <时刻> --tz <IANA>` |
| 阴影短 → 接近正午；阴影偏西 → 下午 | `sun.py ratio --shadow <比>` 得高度角，再 `pos` 定时段 |
| 阴影角度 → 推太阳高度与方位，进而推时段 | `sun.py locate --ratio <比> --shadow-bearing <方位>` |
| 已知太阳方位角与高度角 → 反推日期与时刻并给误差 | `sun.py when --at <地点> --dates <区间> --elev <角> --shadow-bearing <方位>` |
| 影子推得地方时，再按经度换算（每 15° = 1 h） | `sun.py when`（国内另有「统一北京时间 = 经度线索」，见下） |
| 影子方向 + 街道走向 → 判道路走向 | `sun.py street --at <城市> --date <日期> --shadow-rel 90` |
| 物体受光面朝拍摄者 → 太阳在拍摄者背后 | `sun.py facing --at <位置> --time <时刻> --lit <面> --shaded camera` |
| 太阳位于画面左侧 → 左右对应东西 | `sun.py compass --sun-x <像素> --width <图宽> --hfov <视角>` |
| 屋顶太阳能热水器普遍朝南 → 定南北轴线 | `sun.py facing`（把墙面法向换成板朝向） |
| 户户通小锅朝向 → 经度范围 | `sun.py dish --lat <纬> --sat 92.2 --azimuth <方位>` |
| 积雪/常绿等**物候、气候、纬度带**规则 | 不计算，留在散文规则里按季节月份套 |

**国内特有**：全国用东八区时间，国土横跨 73°–135°E。太阳正午（影子指正北）的北京时间：上海≈11:56、
兰州≈13:06、拉萨≈13:57、乌鲁木齐≈14:11。**知道钟表时间 + 看得出影子方向，就能直接卡经度**——
下午两点影子还指正北，不可能在东部。

## 4. 进候选盘（与 wlmz 的接口）

`sun.py locate` 的输出是「一条带」，必须**与已判读出的候选区求交**，不能单独当结论：

```bash
uv run scripts/sun.py locate --time 2023-08-15T16:20 --tz Asia/Shanghai \
    --ratio 1.2 --tol 1 --bbox 34,110,42,122 --mosaic north.jpg --out band.jpg
# 再加影子朝向，带会缩成一段
uv run scripts/sun.py locate ... --shadow-bearing 60 --az-tol 10
```

- 结果按 `geo-sleuth/SKILL.md` 第 2 步 `board.py evidence --for ... --against ... --file band.jpg` 进候选盘。
- 报结论时换成 `wlmz` 的 L0–L4（映射表在 `wlmz/SKILL.md`）。
- 没有时刻时，**不要**用太阳方向单推路向/河流走向/航向——太阳在画面侧面只说明镜头与太阳大致垂直，
  上午正午下午对应的方向完全不同。这条是散文规则库里也写明的红线。

## 5. ShadowFinder（外部工具）

Bellingcat 出品，**输入物高 + 影长（或直接给太阳高度角）+ 日期 + 时刻，输出全球「这条影子可能出现在哪」的亮带图**。
仓库：`https://github.com/bellingcat/ShadowFinder`；本目录下已放源码 `<本目录>/ShadowFinder-main/`。

### 什么时候用它，而不是 `sun.py locate`

| | `sun.py locate` | ShadowFinder |
|---|---|---|
| 范围 | 需 `--bbox`，在候选区上求带 | **全球** |
| 约束 | 影长比 **+ 影子方位角**，`--tol`/`--time-tol` | 只有影长比或高度角 |
| 输出 | `band.jpg`，可直接进候选盘 | cartopy 世界地图 figure，适合看/讲 |
| 依赖 | 无额外（stdlib `ZoneInfo`） | cartopy、matplotlib、pandas、suncalc、timezonefinder |
| 接入 | 已是流程一环 | 交互探索、Colab |

**结论：默认用 `sun.py locate`（超集，且能进证据链）；只有在「不知道大致区域、想先看全球带」
或「要在 Colab 里给人演示」时才用 ShadowFinder。**

### 安装（本机已装好，推荐"走源码"）

**本机状态**：已实测跑通。依赖已装（cartopy 0.26.0 / matplotlib 3.11.2 / pandas / suncalc / timezonefinder 6.0.1 / fire），
`shadowfinder` 包已装（非 editable），并已实测 `find_shadows()` + `plot_shadows()` 断网可用。

**推荐：直接用源码，不装包。** 这样升级/换机器都不依赖 site-packages：

```bash
# PowerShell（仓库根目录）
$env:PYTHONPATH="$PWD\lighting-astronomy\ShadowFinder-main\src"
py -m shadowfinder find 10 5 2024-02-29 13:59:59 --time_format=utc

# Git Bash / macOS / Linux（仓库根目录）
export PYTHONPATH="$PWD/lighting-astronomy/ShadowFinder-main/src"
py -m shadowfinder --help
```

要装成包时：

```bash
py -m pip install --no-deps "<本目录>/ShadowFinder-main"     # 依赖按第 6 节装
```

> ⚠️ **不要用 `pip install -e`（editable）**。中文路径下**必然失败**：pip 把 `.pth` 写成 UTF-8，
> 而 Python 的 site 模块按系统默认编码（中文 Windows 是 GBK）读 `.pth` →
> `UnicodeDecodeError: 'gbk' codec can't decode byte 0xad` → 路径被静默丢弃 → `ModuleNotFoundError`。
> 本机已踩过这个坑，用上面的 `PYTHONPATH` 或非 editable 安装绕过。

> ⚠️ **依赖装不上时**：`pip install shadowfinder` 会去编译 `timezonefinder` 的 C 扩展，需要
> MSVC Build Tools，通常直接失败。用 `pip install --only-binary :all: "timezonefinder<7"` 拿预编译 wheel，
> 再把 `h3` 降到 `<4`（`timezonefinder 6.x` 调的是 h3 v3 的 `geo_to_h3`，h3 v4 已删除该 API）。

### CLI

```bash
py -m shadowfinder find      <物体高> <影长>   <YYYY-MM-DD> <HH:MM:SS> --time_format=utc
py -m shadowfinder find_sun  <高度角>          <YYYY-MM-DD> <HH:MM:SS> --time_format=utc
py -m shadowfinder generate_timezone_grid      # 生成 timezone_grid.json（换机器时）
```

注意参数顺序是 `物体高 影长 日期 时刻`，且 `--time_format` 默认是 `utc`。
**CLI 不打印结果**，直接把图写到当前目录（实测文件名形如 `shadow_finder_20240229-135959-Utc_10_5.png`，1200×600）。
CLI 没有缓存策略，`timezone_grid` 每次都会重算，很吃资源——所以更推荐下面的 API。

### Python API（推荐）

```python
from shadowfinder import ShadowFinder
import datetime

finder = ShadowFinder()
try:
    finder.load_timezone_grid()          # 本目录已附 timezone_grid.json（3.1 MB）
except FileNotFoundError:
    finder.generate_timezone_grid(); finder.save_timezone_grid()

finder.set_details(
    date_time=datetime.datetime(2024, 2, 29, 13, 59, 59),   # 无时区的 datetime
    object_height=10,                    # 物高，任意单位
    shadow_length=5,                     # 影长，同单位；或改传 sun_altitude_angle=<度>
    time_format="utc",                   # 'local' 或 'utc'
)
finder.find_shadows()
fig = finder.plot_shadows()
fig.savefig("out.png", dpi=100)
```

实测：`find_shadows()` + `plot_shadows()` **不需要任何在线接口**（已断网验证）；
`plot_shadows()` 首次会从 Natural Earth 下海岸线数据并缓存到 `~/.local/share/cartopy/`（本机已缓存 0.6 MB）。

### 与本仓库的对接

1. ShadowFinder 的输出是**探索性**的，不能替代 `geo-sleuth/scripts/evidence.py` 的证据图。
2. 它给的全球亮带 → 与 `wlmz-region` 判读出的候选国/省**求交**，再回到候选盘；
   这一步和 `sun.py locate --bbox` 完全同构，只是范围先放全球。
3. 时区一律用 IANA 名（`Asia/Shanghai`），别手写 +8。
4. 本目录已附 `ShadowFinder-main/timezone_grid.json`，可直接 `load_timezone_grid()`，省去生成。

## 6. 依赖与平台（全部本机实测）

> **原则：能本地走源码就走源码，不走在线服务。** ShadowFinder 本来就是纯本地的
> （`suncalc` + 本地 `timezone_grid.json` + 本地 matplotlib），没有任何在线接口依赖——已断网验证。
> 官网那个 Colab 只是给懒人的壳，不是必需入口。

| 工具 | 怎么跑 | 备注 |
|---|---|---|
| `sun.py` / `geo.py` / `clues.py` | `py scripts/sun.py ...` | 纯 stdlib，无网络依赖，可离线。**本机没有 `uv`**，原文的 `uv run` 一律换成 `py` |
| ShadowFinder CLI/API（走源码） | 设 `PYTHONPATH` → `py -m shadowfinder ...` | 见第 5 节；不装包也能跑 |
| ShadowFinder 依赖 | `cartopy` `matplotlib` `pandas` `suncalc` `timezonefinder` `fire` | 本机已装；cartopy 0.26.0 有 cp311 Windows 预编译 wheel，**不需要 conda** |
| ShadowFinder Colab | 浏览器 | 仅在「想在别人机器上免安装演示」时用 |

**Windows 三个坑（都实测踩过）**：

1. `pip install -e` 在中文路径下必然失败（`.pth` 编码不匹配，见第 5 节）→ 用 `PYTHONPATH`。
2. `pip install shadowfinder` 会尝试编译 `timezonefinder` 的 C 扩展 → 需 MSVC，通常失败 → 用 `--only-binary`。
3. 脚本输出路径写 `/tmp/...` 会被解释成 `\d\tmp\...` → 用 `D:/tmp/...` 或相对路径。

**ShadowFinder 在技能目录里的位置**：`lighting-astronomy/ShadowFinder-main/`（17 文件，3.3 MB，其中
`timezone_grid.json` 占 3.1 MB）。它**不含 `SKILL.md`**，所以不会跟 26 个技能抢扫描/触发。
