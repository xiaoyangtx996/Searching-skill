# Chronolocation：用太阳与阴影定位（Bellingcat 方法）

> **旁挂**：`SKILL.md` 是「线索 → 结论」规则表；本文是从 OSINT 侧导入的**系统方法**，补足「怎么把太阳/阴影变成机位」。
> 素材来源：Bellingcat《Using the Sun and the Shadows for Geolocation》(2020-12-03) 中译本（本地 `SunCalc.org-光影定位/`）。
> 本地等价计算脚本：`geo-sleuth/scripts/sun.py`（与 NREL SPA 对比误差 ≤0.02°）；交互工具：SunCalc。

## 概念

**Chronolocation（定位计时）** = 用**画面里的太阳/阴影**把「拍摄时刻」和「拍摄位置」绑在一起：
- 已知位置 → 由太阳高度/方位反推**时刻**
- 已知时刻 → 由太阳方位反推**朝向**，由高度角反推**纬度带**
- 位置、时刻、影长三者**已知两个就能定第三个**

## 操作流程（四步）

1. **取时间戳**：视频/图片的发布时间、故事上传时间、EXIF。注意时区归算（UTC vs 当地时间）。
2. **读画面**：太阳在画面里的位置（左/右/正前）、影子的方向与长度、海洋/道路的走向。
3. **代入 SunCalc**：选日期，拖时间滑块，比对该时刻的太阳方位角与高度角。
   - 例：链接式定位 `https://www.suncalc.org/#/38.7068,-9.166,12/2020.11.22/16:31/50/1`
4. **排除候选**：由「太阳在西南 → 拍摄者朝南」「水面在南 → 排除内陆与大河北岸」等，逐一砍掉候选，直到唯一。

## 推断口诀

- 太阳所在方位 = 影子指向的**反方向**
- 拍摄者朝向 ≈ **面向太阳**时，太阳方位角即为镜头朝向（越接近正对越准）
- 画面右侧是海、太阳又在海面上 → 该海在该城市**西南或西**；结合地形排除内陆
- 已知经度+日期 → 太阳时角唯一确定；纬度决定高度角（**夏天高、冬天低**）
- 影子长度/本体高度 = `1/tan(太阳高度角)`（本地表见第 2 节）

## 与本仓库的接口

| 需求 | 用什么 |
|---|---|
| 由位置+日期+时刻算太阳方位/高度 | `py geo-sleuth/scripts/sun.py pos` |
| 由影长比反推太阳高度角 | 本文第 2 节表 / `sun.py` |
| 由太阳像素反推镜头朝向 | `geo-sleuth/scripts/pose.py` |
| 由时刻+影子方位约束候选带 | `py geo-sleuth/scripts/sun.py locate` |
| 想要「全球亮带地图」可视化 | `lighting-astronomy/ShadowFinder-main/`（见 `影子与太阳·本地计算.md` 第 5 节） |

## 与其它技能的接缝

- 影子**方位** → 判南北与道路走向（`maps-streetview`）
- 影子**长度 + 本体高度** → 定纬度带与季节（本节 + `sun.py`）
- 有night-sky/月相 → 更精细的时角定位（`night-sky`）
- 有云 → 可交叉天气日期（`weather-climate`）

## 提醒

- 该方法**只做筛选与排除**，通常不能单凭太阳给出精确坐标；必须与固定地物（道路、建筑、海岸线）交叉。
- 时区、夏令时、手机时钟误差都会污染结论——先核时间源。
- 阴影测长只在**影子与本体同平面**时成立；斜投影要按透视修正。
