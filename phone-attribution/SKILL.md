# 号码归属查询

由画面里的**电话号码**反查位置。分两条路：

| 号码类型 | 走哪条 | 网络 |
|---|---|---|
| **11 位手机号** | `phone_lookup.py`（本地 `phone.json`，无索引则直接扫库） | ❌ **零网络** |
| **座机号**（区号+本地号） | chahaoba.com `api.php` 反查单位名与坐标 | ✅ 需联网 |

> 数据源：
> - **本地号段库**：`phone.json`（483,977 条，字段：`prefix_3` `prefix_7` `middle_4` `operator` `province` `city` `area_code` `postal_code`）
> - **座机单位库**：[查号吧 chahaoba.com](https://www.chahaoba.com/)（MediaWiki，网友提交的「单位电话归类」结构化条目）
>
> 本技能是**查询方法 + 边界闸门**，不是自动爬虫；chahaoba 部分按站点 robots.txt 合规，一律用 `api.php`。

## 何时加载

- **11 位手机号**出现（招牌、车身、海报、门头）→ **优先走本地号段库，不依赖任何云端 API**
- **门头、招牌、广告牌、围挡、横幅上有座机号** → 走 chahaoba
- 售楼广告上的售楼热线（唯一性高，可直接反查项目与县市）
- 单位门口公示牌、施工告示上的联系号码
- 已从画面读出区号，想进一步落到**单位/街道级**

**不适用**：400/800 号、短号（110/119/12345）。

## 使用方式

从仓库根目录执行。没有 `python` 就用 `py`。

| 步 | 输入 | 立刻做 | 输出 |
|---|---|---|---|
| 1 | 画面上的号码串 | 去空格/`+86`；数位数；看是否 `1` 开头 | 类型：中国手机 / 座机 / 外国号 / 400·800·短号 |
| 2 | 中国手机（11 位且 `1` 开头） | `python phone-attribution/phone_lookup.py 13912345678` | `province` `city` `operator`；本领域止于市级倾向 |
| 3 | 座机（含区号） | 先离线 `geo-sleuth/data/cn_area_codes.json` 或 `python geo-sleuth/scripts/clues.py lookup area-code 010`；再剥区号，只用本地段查 chahaoba `api.php` | 区号级 或 `{{单位电话归类}}`；坐标=单位地址≠机位 |
| 4 | 400/800/110/119/12345 | **不适用本技能**，改查画面其它文字 | L0 |
| 5 | 步骤 2–3 结论 | 交回总技能 | 不报 L3+ |

无命中 → 换领域。条件冲突 → 跳过。只命中 1 条 → 止于倾向。
回传行：规则摘要：<号码 → 归属地/单位>

| 触发 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 号码被遮挡/少一位 | 按可见部分列号段范围 | 只报运营商 |
| 手机号查不到 | 按新号段/虚拟运营商处理 | 只报"归属地库未收录" |
| 座机查不到条目 | 换切割位置或按单位名反搜 | 只报区号级 |
| 命中但信息是十年前的 | 见「三、边界」，降权 | 不当 L3+ 依据 |
| 仅命中1条 | 结论止于倾向 | 请用户补图或交叉其它领域 |

### 🔴 CHECKPOINT · 🛑 STOP

查完号段/单位后、把「市」写进候选前：画面须另有独立线索（门头文字、路牌、街景），否则 **停在倾向**，不报 L3+。
用户只要「定到哪栋楼」且本地号不全/仅区号 → **停**，套黄金出货 B。
**号码库大多是多年前的用户提交，只能当线索，不能当铁证。**

## 一、手机号：本地号段库（零网络，优先走这条）

> ⚠️ **前提：只有确定是"中国大陆手机号"才走这条。**
> 别看到"11 位数字"就往这个库里套——国外也有 11 位号码（含国家码的英/美/日号码等）。
> **判定条件（三条同时满足）**：① 11 位 ② **以 `1` 开头**（中国手机号全部 `1` 开头）③ 前 7 位在 `phone.json` 里有记录。
> 不满足任一条 → **不是中国号，不要用这个库**，按该国号码规则另判（见「先判是不是中国号」）。

**核心原则：确认是中国手机号后，一律先查本地库，不调用任何云端 API。**

```bash
py phone-attribution/phone_lookup.py 13000001234
py phone-attribution/phone_lookup.py "+86 139 1234 5678"     # 自动剥离 +86/空格
py phone-attribution/phone_lookup.py 13000001234 --json      # 给 board.py 用
py phone-attribution/phone_lookup.py --stats                 # 看库规模
```

实测输出：

```
13000001234  中国联通  山东济南
  区号 370100  邮编 250000  号段 1300000

13912345678  中国移动  江苏常州
  区号 320400  邮编 213000  号段 1391234
```

### 先判是不是中国号（**必须**）

| 现象 | 判断 | 怎么做 |
|---|---|---|
| 11 位、`1` 开头、号段有记录 | ✅ 中国手机号 | 走本地库 |
| 11 位、`1` 开头、号段**无记录** | ⚠️ 新号段或未入库 | 报"未收录"；再试 chahaoba |
| **11 位但不以 `1` 开头** | ❌ **不是中国号** | **不要用这个库**，按该国规则 |
| 位数不是 11（如 10 位、12 位） | ❌ 不是中国号 | 按该国规则 |
| **前面有 `+` 国家码且不是 `+86`** | ❌ 外国号 | 按该国规则（如 `+44` 英国、`+1` 美加、`+81` 日本） |
| `1` 开头但画面明显在境外 | ⚠️ 存疑 | 别硬套；境外场景优先信画面线索 |

**关键**：`+81-90-1234-5678`（日本）是 11 位数字，**但它不是中国号**，
剥掉 `+81` 后的 `9012345678` 是 10 位——**这种绝不能进本地库**。

其他常见 11 位情形：含国家码的英国号码 `+44 7911 123456`、美国 `+1 555 123 4567`、
日本手机 `090-1234-5678`。**判据永远是「是否中国号段」，不是「是否 11 位」。**

### 字段怎么用（8 个字段全用上）

| 字段 | 值例 | 定位价值 |
|---|---|---|
| `prefix_3` | `130` | **运营商** — 见下方实测对照表 |
| `prefix_7` | `1300000` | 前 7 位，最细粒度（= `prefix_3` + `middle_4`） |
| `middle_4` | `0000` | **第 4–7 位**，查询时取号码的 `[3:7]` |
| `operator` | 中国联通 | 运营商。**查表直接读它，别自己背号段** |
| `province` | 山东 | **省级**，直接可用 |
| `city` | 济南 | **市级**，直接可用 |
| `area_code` | 370100 | **行政区划代码**（GB/T 2260）→ 可查区县层级 |
| `postal_code` | 250000 | **邮编**，交叉验证用 |

**最有价值的三个**：`city`（市级直接落点）、`area_code`（能反查行政区划）、`postal_code`（独立交叉验证）。

### 运营商号段对照（从 `phone.json` 实测统计，非印象）

| `prefix_3` | operator |
|---|---|
| 130 131 132 | 中国联通 |
| 155 156 166 175 176 185 186 196 | 中国联通 |
| 133 153 173 177 180 181 189 190 191 193 199 | 中国电信 |
| 135 136 137 138 139 150 151 152 157 158 159 | 中国移动 |
| 172 178 182 183 184 187 188 195 197 198 | 中国移动 |
| **192** | **中国广电**（唯一一个，别归错） |
| 162 | 中国电信/虚拟运营商 |
| 165 | 中国移动/虚拟运营商 |
| 167 171 | 中国联通/虚拟运营商 |
| **170** | **混合**：联通 39% / 移动 30% / 电信 30% |
| 145 146 147 148 149 | 数据上网卡 / 物联网卡（**不作定位依据**） |
| **134** | **不纯**：移动 89% + 电信/卫星电话卡 10% |
| **141** | **不纯**：联通 51% + 电信/物联网卡 48% |
| **174** | 卫星电话卡（电信 57% / 应急通信 39%） |

**要点**：`134` `141` `170` `174` **不是单一运营商**，别按"134 开头就是移动"直接下结论。
`14x`/`16x`/`17x` 里的物联网卡、卫星卡是**设备专用**，出现在照片里的概率低，且**无定位意义**。

### 查询原理

`prefix_7` = 号码前 7 位，**全局唯一**（483,977 条无重复），所以：

```
号码 130 0000 1234
     └┬─┘ └┬─┘
   prefix_3  middle_4  → 经纬度无关，直接命中归属地
```

`phone.json` 约 483,977 条。查询：号码前 3 位 + 第 4–7 位命中 `prefix_7`。可选：目录里若有 `phone_index.json` 则 `phone_lookup.py` 优先用索引，没有就扫 `phone.json`。

### 手机号做不到什么（先说清，别误用）

- **查不到机主、单位名**。数据是**号段→归属地**，不是"谁在用"。
  → 想知道**具体单位**，只有座机那条路（chahaoba）。
- **不保证精确到当前所在地**：号码归属地 ≠ 拍摄地。**异地使用极常见**（出差、打工、外地号）。
  号段归属地只能作为**弱线索**，必须和画面线索交叉。
- **`prefix_3` 只能到"运营商"，`prefix_7` 才能到"省市"。** 号段归属地的粒度是**市**，不是区县。
- **虚拟运营商号段（16x/17x）归属地规则最乱**，实测部分号段归属地不准。
- 新号段未收录 → 报"号段无记录"，此时可回退 chahaoba 查。

## 二、座机号：chahaoba.com（联网）

**接口**：`https://www.chahaoba.com/api.php`（MediaWiki 原生 API，robots **未禁**）

> ⚠️ 站点页面搜索框背后是 `/wen_api/es_api.php`，**robots.txt 明确 Disallow，不要调它**。
> 用 `api.php` 即可达到同样效果。

### 1. 抄号码：一定要"切出本地号码段"

**这是最容易踩的坑。** 同一个号码，写法不同结果天差地别：

| 你输入的 | 结果 | 结论 |
|---|---|---|
| `06603461119`（连写） | **0 命中** | ❌ 千万别这么查 |
| `0660-3461119`（全带区号） | 6874 命中（全是噪声） | ⚠️ 太多，要自己翻页 |
| **`3461119`（只取本地段）** | **1 命中，精确** | ✅ **正确做法** |

**做法**：区号从号码里剥掉，用**剩下的本地号码段**当搜索词。
中国固话本地段通常是 **7 位**（8 位区号城市）或 **6-8 位**（3-4 位区号城市）。
抄不全或抄错一位时，**换切割位置多试几次**。

### 2. 搜索 + 取正文

```bash
# ① 搜（用本地号码段）
curl -s "https://www.chahaoba.com/api.php?action=query&list=search&srsearch=3461119&format=json&srlimit=5"

# ② 用上一步的 pageid 取 wikitext
curl -s "https://www.chahaoba.com/api.php?action=parse&pageid=3717125&prop=wikitext&format=json"
```

也可按 **单位名** 反搜（`--srsearch=汕尾市捷胜边防派出所`），但实测 wiki 全文检索对**长单位名不敏感**（本例 0 命中），
**优先用号码段**。

### 3. 解读正文：先看是"哪一类页面"

wiki 条目有**两类**，识别错会白忙：

| 模板 | 内容 | 价值 |
|---|---|---|
| `{{单位电话归类\|...}}` | **结构化**：单位名、地址、类别、邮编、乡镇、**经纬度**、邻近单位 | ✅ **要的就是它** |
| `{{查询要求顶部}}` | 网友**提问帖**，常只有区号级回复（"广东汕尾市，具体无法查到"） | ⚠️ 只能给区号级 |

### 4. `{{单位电话归类}}` 字段表（4 个样本实测，19 字段稳定）

```
{{单位电话归类|单位名|详细地址|城市|类别|...|邮编|...|街道|区划|经度|纬度|备用号码|邻近单位|邻近单位地址|居委会}}
```

| # | 字段 | 例（0660-3461119） |
|---|---|---|
| 1 | **单位名** | 汕尾市捷胜边防派出所 |
| 2 | **详细地址** | 广东省汕尾市城区捷胜镇捷胜北门车站斜对面 |
| 3 | 城市 | 汕尾 |
| 4 | 类别 | 派出所（另有：体验馆／企业／其它餐饮…） |
| 7 | 邮编 | 516624 |
| 10 | **街道/乡镇** | 捷胜镇 |
| 11 | 区划全称 | 广东省汕尾市城区捷胜镇 |
| 12 | **经度** | 115.453198 |
| 13 | **纬度** | 22.718036 |
| 14 | 备用号码 | 06603493168 |
| 15 | 邻近单位 | 北门社区居委会 |
| 16 | 邻近单位地址 | 汕尾市城区捷胜镇北门社区后山头 |

**注意字段 12/13 是「经度在前、纬度在后」**（115.4 是经度、22.7 是纬度，广东）。
写进候选盘时按 `board.py` 的 `lat,lon` 顺序**换过来**。

字段 15/16 的街道办/居委会名 → 行政区线索（交叉用）。经度在前、纬度在后 → 写入 `board.py` 时换成 `lat,lon`。

## 三、边界（与反例黑名单合并执行）

| 号码/情况 | 止于 | 禁止 |
|---|---|---|
| 手机号段命中 | 省市倾向 | 当拍摄点；报 L3+ |
| 座机单位坐标 | 单位地址级候选 | 当机位 |
| 400/800/短号 | L0 | 查本库 |
| 总部/连锁号 | 企业倾向 | 当地点独有 |
| 十年前条目 | 弱线索 | 当仍营业的排除依据 |
| 库无收录 | 「未收录」 | 「号码不存在」 |

升 L3+：门头文字 + 单位名 + 街景三者一致，且过 STOP。  
顺序：先 `cn_area_codes.json` / `clues.py` 离线缩城 → 再 chahaoba 查单位。
