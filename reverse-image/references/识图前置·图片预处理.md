# 识图前置·图片预处理（旁挂）

> **旁挂文件**：`SKILL.md` 是「线索 → 结论」规则表；本文补足**「识图/读字之前，先把图处理干净」**。
> 素材来源：用户自备经验（网络迷踪入门指南）+ `geo-sleuth/scripts/imgprep.py` 已有能力。

---

## 一、为什么必须预处理

用户原话：

> 「识图，通过百度图片，搜狗图片，google 图片，抖音识图等对图片进行识别，可直接找到位置，
> **如果图片里有遮挡物，可以对图片进行处理，通过 photoshop 进行魔法棒消除，或者识别图片局域部分**」

**核心逻辑**：
1. 反搜引擎会**被遮挡物干扰**（人物、水印、贴纸、无关前景）→ 删掉它，命中率上升
2. **整图搜不到是常态** → 换**局部紧裁**再搜
3. 小字/远牌**直接读不出** → 先放大，再读

---

## 二、三类操作

### 1. 去遮挡（PS 魔法棒 / 内容识别填充）

**做什么**：抹掉画面里的**人物、车牌、水印、贴纸、栏杆**等干扰物，让引擎专注主体。

| 工具 | 说明 |
|---|---|
| Photoshop | 魔棒选中 → 编辑 > 内容识别填充（最常用） |
| **cleanup.pictures** | https://cleanup.pictures/ （**免安装、涂一下即去**，最省事） |
| 在线版 photopea | https://www.photopea.com/ （免装，功能近似 PS） |
| GIMP | 开源替代 |

**本地替代**：`geo-sleuth/scripts/imgprep.py variants` 可做**紧裁**，直接绕开遮挡物
（比消除更快，且不引入伪造内容）。

> ⚠️ **诚实性要求**：消除只用于**搜索**，**不得**把消除后的图当作"画面可见证据"。
> 输出里引用线索时，必须回到**原图**核对（见 `docs/证据与置信度框架.md`）。

### 2. 局部紧裁（比消除更常用）

**做什么**：只把**关键局部**（一个招牌、一块路牌、一辆车）裁出来单独搜。

```bash
# 本地脚本：裁一块并放大锐化（读小字、看车牌底色）
py geo-sleuth/scripts/imgprep.py zoom photo.jpg --box x0,y0,x1,y1 --out zoom.png
# 切 N×M 网格，逐块搜
py geo-sleuth/scripts/imgprep.py grid photo.jpg --rows 2 --cols 2 --out tiles/
```

**顺序建议**：先 `zoom` 读细节 → 再 `variants` 出变体批量搜 → 最后才考虑消除。

### 3. 无损放大（读远牌 / 小字）

| 工具 | 链接 | 说明 |
|---|---|---|
| Bigjpg | https://bigjpg.com/ | AI 放大，动漫/照片 |
| Upscale.media | https://www.upscale.media/ | 免登录 |
| 佐糖 | https://picwish.cn/ | 国产，可放大+去噪 |
| Real-ESRGAN | 本地开源 | 批量，需显卡 |
| Waifu2x | https://waifu2x.udp.jp/ | 老牌 |

**注意**：AI 放大是**推测生成**，可能"无中生有"字符。
**判读铁律**：放大后读出的字**必须回原图复核**——只在一个版本出现、原图看不到的，不能采信
（同 `docs/证据与置信度框架.md` 对 OCR 多 pass 一致性的要求）。

## 三、反搜引擎清单（用户点名 + 本地方案已有）

| 引擎 | 链接 | 特点 |
|---|---|---|
| **百度识图** | https://graph.baidu.com/ | 中文网页/微博/百家号覆盖最好，会给「图中可能是…」 |
| **搜狗图片** | https://pic.sogou.com/ | 中文补充 |
| **Google 图片 / Lens** | https://lens.google/ | **最强**，能直接给地名（实测） |
| **抖音识图** | 抖音 App「识图」 | 生活化场景、国内小店 |
| **Yandex** | https://yandex.com/images/ | 建筑、外国内容强 |
| **Bing 视觉搜索** | https://www.bing.com/visualsearch | 补充 |
| **TinEye** | https://tineye.com/ | 找最早出处 |

> 本项目 `geo-sleuth/scripts/revimg.py`（百度+Yandex）与
> `image-search-mcp`（Google Lens+百度+Bing）已可自动化；
> 抖音识图、搜狗图片**需人工**（有 App 限制/反爬）。

## 四、推荐执行顺序

```
原图
 ├─ ① exif.py           读元数据（有 GPS 直接完事）
 ├─ ② imgprep edges     看四边四角（易漏的路牌/缆绳/船头）
 ├─ ③ imgprep zoom      放大关键局部 → ocr.py 读字
 ├─ ④ imgprep variants  出变体（紧裁/翻转/去色偏）→ 多引擎搜
 ├─ ⑤ （必要时）PS 消除遮挡 → 再搜一轮
 └─ ⑥ 放大远牌/小字 → 回原图复核
```

**一步都不要跳**：用户经验里"图片无损放大"和"局部识别"是分开两步，
前者救**模糊**，后者救**干扰**，解决的问题不同。

---

## 五、局限

- 消除遮挡**会改变画面**，只能用于搜索，不能当证据
- AI 放大**会编造细节**，"放大后才有的字"不可信
- 反搜引擎**都有配额与反爬**，失败是常态；一个引擎无果≠图上没线索
- 局部紧裁**丢失上下文**：只搜局部可能命中"同款物件"而非同一地点，
  必须**回整图**用其他线索交叉验证
