## 四、社交与内容平台（实景来源）

大众点评、微博、抖音、小红书、B 站 —— 搜「地点 + 实拍」，常有官方/游客照片，
可与目标图比对招牌、店招、楼体细节。**注意**：这些是**旁证**，不是坐标。

## 四·补、房源平台 → 小区内部/外部实景（**专治小区内景**）

**场景**：照片是**小区内部**（楼栋、单元门、绿化、地库、电梯厅）或**小区外立面**、
**沿街门脸**。这类图没有路牌、没有车牌，常规街区方法全部失效。

**突破口**：房源网站的**实景图库**——中介为了卖房，会把小区内外拍个遍，
而且**带楼栋号、单元号、面积、价格**。一张小区内部照片，常常能在房源图库里
找到**几乎同一机位**的照片，直接锁定小区名。

| 平台 | 链接 | 特点 |
|---|---|---|
| **链家** | https://lianjia.com | 图最全（含**小区实景、单元门、楼道、地库**），有楼层/朝向/建成年份 |
| **贝壳** | https://ke.com | 链家同源，覆盖更广，有 VR 看房 |
| **安居客** | https://www.anjuke.com | 小区详情页有实景相册 |
| **58 同城** | https://www.58.com | 房源量大，图片杂（含个人房源实拍） |
| **我爱我家** | https://www.5i5j.com | 北方城市覆盖好 |
| **幸福里** | https://www.xingfuli.com | 字节系，小区资料+实景 |
| **720 云** | https://720yun.com | 商拍全景，楼盘/样板间 |

### 用法（关键是**从图里能读出的东西反查**）

1. **读门牌/楼栋号**：单元门上的「X 号楼」「X 单元」+ 小区名 → 直接搜小区
2. **读特征物**：独特的门头造型、单元门样式、地库坡道、健身器材、雕塑
   → 在房源图库里比对（同一小区不同楼栋的单元门往往同款）
3. **读文字**：物业告示、电梯广告、快递柜品牌、门禁机品牌 → 缩小城市/物业公司
4. **读外立面**：涂料颜色、瓷砖规格、飘窗样式、空调机位排布
   → 搜「城市 + 小区 + 实景」，比对图库
5. **交叉验证**：房源页有**建成年份、层数、户型**，与照片里的建筑特征对得上才成立

### 限制（必须说明）

- 房源图**有很强的时效性**：小区可能已翻新、门店已换、树木已长大
- 链家/贝壳的图**多为广角**（显得空间大），与手持照片的透视不一致
- **不是所有小区都有房源**：老破小、单位家属院、县城小区常常没有
- 房源平台**有反爬**，脚本抓取容易被封；推荐**人工查**（本清单是工具指引，不是抓取脚本）

> ⚠️ **合规**：房源平台 `robots.txt` 多数禁止自动化抓取。
> 本清单只作**人工查询指引**，不提供抓取脚本。

## 五、反向搜图引擎（配合使用）

- **Google Lens** — https://lens.google/ （Chrome 右键）
- **Yandex Images** — https://yandex.com/images/ （人像/建筑最强）
- **TinEye** — https://tineye.com/ （找最早出现）
- **百度识图** — https://graph.baidu.com/
- **Bing 视觉搜索** — https://www.bing.com/visualsearch
- 另见 `reverse-image/SKILL.md` 与 `geo-sleuth/scripts/revimg.py`

## 提醒

- 全景/街景**有时效**：街景车年份不同，店招会变；老照片比对要挑**同期**街景。
- 卫星图**看不出**门牌、店招、楼层数——这些必须靠街景/全景。
- Mapillary 的覆盖**极不均匀**，没有影像 ≠ 没有该地点（不可反证）。
